# PRD — Карта E2E-процесса планирования поставок (In.Plan Process Map)

Версия 1.0 · 24.08.2026 · владелец: Igor D

## 1. Проблема

Описание E2E-процесса Supply Planning живёт в презентации из 6 слайдов. Её нельзя встроить в In.Plan, она не кликабельна, не ведёт на экраны системы, и каждое изменение процесса требует перерисовки слайда. Пользователям In.Plan (планировщикам, аналитикам, новым сотрудникам) нужен живой «навигатор» по процессу прямо внутри системы: увидеть этап, провалиться в шаги, понять входы/выходы и одним кликом перейти на нужный экран.

## 2. Цели

- Дать интерактивную визуализацию E2E-процесса, встраиваемую в In.Plan как iframe.
- Показать 2 уровня: обзор из 4 этапов + детализация шагов каждого этапа с входами/выходами и интеграциями (DP, PS, IO, ERP, MRP).
- Позволить привязывать к шагу или этапу URL экрана в In.Plan и переходить на него.
- Позволить редактировать описание процесса без пересборки приложения (данные — JSON).

## 3. Не-цели (v1)

- Бэкенд, авторизация, многопользовательское редактирование.
- Редактирование топологии графа (добавление узлов и связей мышью).
- Интеграция с API In.Plan, живые данные о предупреждениях и статусах расчётов.
- Мобильная версия.

## 4. Пользователи и сценарии

**Планировщик поставок.** Открывает страницу вики In.Plan с картой процесса, находит шаг «Ограниченный прогноз продаж», читает входы/выходы, жмёт «Открыть в модуле» — попадает на экран расчёта.

**Методолог / бизнес-аналитик (редактор).** Переключается в режим «Редактор», прописывает название экрана и URL для шагов, экспортирует JSON и коммитит его в репозиторий (или передаёт администратору).

**Новый сотрудник.** Проходит по всем 4 этапам, чтобы понять последовательность и связи с внешними системами.

## 6. Нефункциональные требования

- Статический бандл (Vite), без сервера; хостится как папка `dist/` на любом веб-сервере In.Plan или GitHub/Cloudflare Pages.
- Корректно работает в iframe: не зависит от `X-Frame-Options`, ширина/высота 100 % контейнера, `ResizeObserver` для перестроения при изменении размера фрейма.
- Первая отрисовка < 1 с на корпоративном ноутбуке; бандл ≤ 400 KB gzip.
- Только русский язык интерфейса (i18n не требуется, но строки вынесены в один файл).
- Визуальный стиль — по макету Claude Design (папка «Мокеты процесса In.Plan»): токены In.Plan, фирменный фиолетовый `#9000ff` только на активном блоке и главной линии процесса, интеграции `#0d56e2`, предупреждения `#ff9a3b`, шрифт Open Sans.
- Браузеры: Chrome/Edge последних 2 версий.

## 7. Данные

Источник истины — `src/data/process.json`. Содержимое переносится из «SNP Е2Е процесс.pptx» (6 слайдов): 4 этапа, ~40 шагов, входы/выходы, интеграции с DP, PS, IO, ERP, MRP. Схема описана в SPEC.md.

## 8. Метрики успеха

- Карта встроена в страницу In.Plan и открывается без ошибок консоли.
- 100 % шагов из презентации присутствуют в JSON (проверяется тестом).
- Для ≥ 80 % шагов заполнен `screenUrl` силами методолога через режим «Редактор» без участия разработчика.

## 9. Риски

- In.Plan может запрещать навигацию `_top` из iframe (sandbox) — предусмотрен фолбэк `_blank`.
- Хостинг без HTTPS заблокирует iframe в HTTPS-вики — хостинг только с сертификатом.
- Автолейаут графа может давать «некрасивую» раскладку — в v1 координаты узлов фиксируются в JSON, автолейаут (dagre) только как утилита генерации стартовых координат.

## 10. Этапы поставки

1. **M1 — Скелет и данные**: проект Vite + React + React Flow, JSON процесса, обзор уровня 1.
2. **M2 — Детализация и панель**: уровень 2, Drawer, типы узлов, легенда, зум.
3. **M3 — Ссылки и редактор**: screenUrl, режим редактора, localStorage, экспорт/импорт.
4. **M4 — Встраивание**: компактный режим, deep-link, сборка, инструкция по iframe, проверка в In.Plan.
